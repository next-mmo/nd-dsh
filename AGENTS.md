# ND-DSH contributor guidance

- ND owns the product control plane: companies, projects, roles, agents, tasks, skills, memory, policies, provider routes, and coding-engine contracts.
- Keep DeepSeek Harness as an upstream-tracking runtime submodule/adapter (sync to latest at bootstrap or via `dsh:update`; no frozen commit pins during beta). Do not copy or patch its core into this repository.
- Treat DeepSeek as a model-provider compatibility route, not ND product identity.
- Treat Codex and future coding products as replaceable engine adapters. Do not leak engine-specific branching into organization-domain state machines.
- The embedded `WebContentsView` is the canonical browser. Never launch a hidden automation browser for agent tasks.
- Browser tools must share `ND_DSH_AGENT_BROWSER_CONFIG` and `ND_DSH_AGENT_BROWSER_SESSION`.
- Preserve context isolation, renderer sandboxing, loopback-only CDP, and workspace-scoped runtime policies.
- Never substitute mock companies, fake sessions, or demo workspaces in the production renderer when the trusted preload is unavailable; fail closed instead.
- Add desktop capabilities through narrow IPC contracts or engine adapters; do not expose Node directly to React.
- **ND Pencil** is ND's native Freeform design surface and product identity. Normal product UI, IPC names, settings, errors, and documentation must say ND Pencil.
- ND Pencil is **100% in-repo code**: a React/DOM/SVG editor in the trusted renderer plus `DesignSessionService` in main. Do not reintroduce a vendored editor, native editor binary, CanvasKit runtime, loopback design shell, or child `WebContentsView`.
- `.op` is ND's version-2 design document format (`format: "nd-pencil"`, `version: 2`). Legacy 0.8.x documents are imported best-effort, unsupported features are reported, and the original bytes are backed up under `.nd/design/.backups/` before the first v2 write.
- Main owns the authoritative open document, revision, undo/redo, autosave, save conflicts, and file containment. The renderer replica is a view/controller; it must not write `.op` files.
- ND Agent manipulates the live canvas through the typed `nd_design` tool. The default ND Harness reaches it through the authenticated loopback MCP bridge (`scripts/nd-design-mcp.mjs`); the Rust agent reaches it through the broker. Never allow generic workspace tools to write `.op` files.
- The design MCP bridge binds loopback only, uses a per-launch token held in the harness child environment, and accepts only the validated design actions. Do not expose the bridge URL or token to the renderer or to remote content.
- Image nodes use workspace-local assets or bounded data URLs. Do not fetch remote images into the design document.
- Treat `.op` files as Freeform design artifacts, not production application source. Build into App must write a design spec and target the active project's real HTML/React/shadcn/native source, remaining visible as a normal Git diff.
- Do not expose account/login, team/collaboration, cloud tenancy, built-in AI/provider configuration, update/billing, or standalone-app workflows through ND Pencil. ND owns identity, agents, projects, workspace, provider routing, and distribution.
- **Extension scalability**: Optional packages must be external and installed on demand; never add their payloads or package-specific UI dependencies to release `extraResources` or app-shell imports. Publish catalog metadata separately from the app, bound to immutable source revisions and verified file sizes/hashes. Core built-ins are deliberate product capabilities only.
- Extension installation must use the injected nd-core snapshot service in production. Every copied file, including dependencies, must pass caps and symlink checks; never run install/build scripts during installation.
- Web-view background execution is profile-owned and opt-in, bounded by count and idle expiry; always dispose retained views on disable, uninstall, or version change. Native background jobs must reconcile activation/settings and stop when disabled.
- **Security & Secret Safety (Zero-Tolerance)**:
  - **Never commit live API keys, tokens, credentials, or secrets**: Under no circumstances should real API keys (OpenCode, OpenAI, DeepSeek, Anthropic, GitHub, AWS, etc.) be hardcoded in any file, including source code, E2E test fixtures (e.g. `e2e/fixtures.ts`), sample scripts, configs, or documentation.
  - **Environment variables and mocks only**: All tests, E2E suites, and seeds must read credentials from environment variables (e.g., `process.env.E2E_MODEL_API_KEY` from the gitignored `.env.e2e`) with safe fallbacks or use explicit dummy tokens (e.g., `sk-test-placeholder`). In CI workflows, secrets must be passed strictly via GitHub Actions Secrets (`secrets.*`), never inline.
  - **Local secrets & `.env` protection**: Keep `.env*` and local credential files untracked and excluded in `.gitignore`. Never use `git add -f` on ignored files containing environment or runtime state.
  - **Pre-commit diff inspection**: Always verify `git diff --staged` before committing to ensure no private keys, session tokens, or high-entropy credentials are inadvertently introduced.
- Run `pnpm verify`, `pnpm typecheck`, `pnpm test`, and `pnpm build` before publishing changes.
