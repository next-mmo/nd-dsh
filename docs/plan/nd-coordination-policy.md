# ND coordination policy experiment

`ND_DSH_COORDINATION_POLICY=foreground-v1` opts the ND Harness preset into concise child context packets, disjoint file ownership, foreground delegation batches when the parent depends on all results, and bounded diagnostic polling for useful background work. Leave it unset to retain the current default persona byte-for-byte. Other values do not activate the experiment. Restart ND after changing this launch environment variable; saved company policies, model settings and worker limits are not changed.

The policy is guidance, not an enforced scheduler quota. It uses the existing `run_in_background` option and scoped child controls; it adds no public tool/IPC contract and patches no upstream runtime code. Child verification supplements the integrated verification rather than replacing it.

Run `node benchmarks/coordination-policy/run.mjs` against the existing isolated ND benchmark instance at loopback CDP port 9222. The runner stages two benchmark-only presets in that isolated profile, creates fresh workspaces and sessions, and alternates baseline/candidate order for five pairs. Both presets contain the same tools and routes; the only policy difference is the opt-in branch. The saved default stays `nd-dsh`. Trial outputs and raw traces remain under ignored `scratch/coordination-policy`.

The Workspace Checks requirements and frozen scorer are reused. The scorer's only adaptation is its artifact/fixture root. Every check and weight is unchanged. Missing symlink privileges are recorded as unverified, not silently passed. Child lifecycle intervals and model/tool event counts are read from bounded compressed durable journals, validated against the parent and workspace, and stripped of prompts/content. Missing or truncated journals remain unavailable. Model cache state is unavailable. Foreground tool occupancy alone is not child execution evidence.

Promotion is disabled. The acceptance report needs five fully verified matched pairs, at least 20% lower median end-to-end duration, no quality regression, at most four routine parent status polls for two children, and verified actual child overlap. Missing evidence makes the result inconclusive. A successful gate still requires separate review before changing the default.

`node node_modules/vitest/vitest.mjs run tests/nd-coordination-policy.test.mjs` covers opt-in/default rendering, child failure/cancellation/ownership-conflict outcome accounting, unsuccessful verification, missing telemetry, polling budgets and interval accounting. These receipt tests validate the acceptance gate; they do not establish live failure-control behavior or model speed. The live workload supplies the performance evidence. Existing runtime cancellation and workspace-isolation tests remain required.

Codex CLI is outside this ND-only experiment. Any future Workspace Checks CLI run explicitly uses `gpt-6.1-sol` with medium reasoning and permits no fallback model. The earlier Astra receipts remain historical evidence.

The first experiment is complete: five alternating pairs were attempted in 12 fresh performance sessions, with every interruption and blocked arm retained. Three pairs completed both arms; zero pairs were fully verified. Completed-run descriptive medians were 8m45s for baseline and 10m42s for candidate, with parent message events falling from 70 to 43.5 and routine status polls from 13.5 to zero. These unequal completed subsets are not a paired speed ranking. Missing startup hashes, observer context loss, output defects and an unavailable symlink check prevent acceptance. See [full results](../../benchmarks/coordination-policy/README.md).

Actual child journals established overlap in all five candidate attempts, including the blocked last attempt. Token-limit failures and recovery were observed. One foreground child ended aborted after scoped stop; an unfinished background journal leaves background cancellation unavailable. A separate live ownership-conflict/verification fixture preserved the shared file and failed verifier, but its exact label assertion failed; that failure is retained. A fresh v2 fixture clarified the exact A/B labels and passed all seven behavioral assertions, including disjoint outputs, actual overlap and honest failure reporting. Both fixtures are excluded from performance. Default promotion remains disabled.

To continue an interrupted controller explicitly, set `ND_COORDINATION_RESUME=1` and rerun the runner against the same isolated profile. Frozen contract hashes must match. An interrupted attempt is retained and its replacement uses a new session and workspace. The observer fails explicitly on disconnect or lost renderer context; it does not infer success from partial files. `node benchmarks/coordination-policy/finish.mjs` exports terminal receipts and available evidence. `node benchmarks/coordination-policy/fault-cases.mjs` exercises proposed conflicting ownership and a deliberately failed common check separately from timing; existing fault receipts cannot be overwritten.
